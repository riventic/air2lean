# Exporter split: capture in the compiler, renderer outside

Status: B0 (design, equivalence harness, history classification, tag tables). Plan B of the
2026-10-12 architecture plan. Nothing here changes the exporter yet: `zig-patch/air-json/` and the
hook patches are untouched, and so is every compiler cache key.

## Why

Today the whole AIR-JSON writer (`zig-patch/air-json/json.zig`, 2 051 lines, plus `identity.zig`)
is compiled into each patched compiler. Every exporter change, even renaming a JSON field, changes
the compiler key of all four versions (`scripts/cas.py zig_patch_inputs`), so each change costs
four bootstrap builds (~10 min and ~8 GB each, one at a time) on every machine and in CI, and
every open exporter PR conflicts with every other one in the same file.

The split keeps in the compiler only what needs the compiler, and moves the rest out:

| Part | Where | Built with | Changes when |
|---|---|---|---|
| hook | `zig-patch/<version>/hook.patch` | the patched compiler | a new Zig version |
| capture shim | `zig-patch/capture/` (becomes `src/Air/capture.zig`) | the patched compiler | a new compiler fact or forcing point |
| renderer | `zig-patch/render/` | stock Zig 0.17.0, once for all versions | the JSON format, naming, identity rules |

The renderer's output must be **byte-identical** to today's `json.zig` output on every recorded
export before the cut-over (§Equivalence gate).

## Hook

Three call sites, each one line, with names that do not depend on what the shim does:

| Hook | Site | Today |
|---|---|---|
| `funcAnalyzed(&air, pt, func_index)` | `src/Zcu/PerThread.zig`, after `analyzeFuncBodyInner` | `json.zig dumpToDir` |
| `analysisDone(pt)` | `src/Compilation.zig`, once analysis of an update is complete | open PR #172 adds it as `dumpErrorTable`; `codex/c-frontend-libc` adds `checkExports` after `processExports`. One name, `analysisDone`, serves both (to agree with the #172 owner) |
| Sema `for_len` | `src/Sema.zig` `zirForLen` | unchanged: it is a semantic patch (`unchecked_ib`), not an exporter |

`Sema.air_json_unchecked_ib` stays a public declaration the capture reads.

## Capture shim

`capture.zig` runs inside `funcAnalyzed`/`analysisDone` and writes facts, not JSON. It is written
to the following rules:

1. **Same traversal, same forcing.** The capture visits exactly what `json.zig` visits, in the
   same order, and calls the compiler's resolution functions at the same points (§Forcing
   points). The order matters twice: forcing changes the answers of later queries (a struct that
   is only behind a pointer has no fields until its layout is resolved), and interning changes
   the InternPool indices, and so the `__anon_<n>` names, of everything the compiler creates
   later (§Risks).
2. **Exhaustive instruction kinds.** `zig-patch/capture/<version>/tags.zig` (generated by
   `zig-patch/capture/tags.py` from the pinned pristine sources) maps every `Air.Inst.Tag` of the
   version to its kind: the `Air.Inst.Data` field and the `extra` payload the compiler's own
   printer reads. The switch has no `else`: a tag a new version adds is a compile error until it
   has a kind. The renderer, not the capture, decides how a tag is written (explicit arm,
   `"unsupported": true`).
3. **Reflection, not field lists.** The `data` field and the `extra` payload of each instruction
   are serialized by `@typeInfo` over the payload type; an `Air.Inst.Ref`, `InternPool.Index`,
   `Nav.Index` or `NullTerminatedString` field is recorded as a typed reference and its target is
   added to the closure. InternPool keys (`indexToKey`) of everything reached are serialized the
   same way, so the facts carry every raw field even if `json.zig` reads only some.
4. **Fixed computed queries.** What is not a raw field (sizes, offsets, layouts, names a
   function computes) is answered by a fixed list of queries (§Computed queries), each recorded
   at the point `json.zig` asks it. A new query is a capture change; a new use of a recorded
   answer is not.
5. **Identity raw data.** The capture records the owner identities the renderer needs to enforce
   §Identity (compilation, `Nav.Index`, module of a file, `main_mod`/`std_mod`), and the
   canonical encoding inputs of generic instances; the renderer computes `instance_key`, claims
   and filenames.

### Facts schema `air2lean-facts/1`

One JSON file per analysed function that passes `ZIG_AIR_JSON_FILTER`, in `ZIG_AIR_FACTS_DIR`
(named like the output file, with `.facts.json`), and one `analysis.facts.json` per compilation
written by `analysisDone`. Draft:

```jsonc
{
  "facts": "air2lean-facts/1",
  "zig_version": "0.17.0",
  "compilation": 1,                      // per-process ordinal of the Zcu (sub-compilations differ)
  "unchecked_ib": ["for_len"],           // Sema.air_json_unchecked_ib, if declared
  "profile": { "target": {...}, "backend": "stage2_llvm", "optimize": "safe", ... },
  "func": { "ip": 1234, "owner_nav": 56, "fqn": "basic.scale", "module": "root",
            "src": {"file": "basic.zig", "module": "root", "decl_line": 14},
            "linkage": "export", "ty": 1230 },
  "body": [17, 18, 19],                  // main body instruction indices
  "insts": {
    "17": { "tag": "arg", "kind": "arg", "ty": 1231, "data": {"ty": 1231, "zir_param_index": 0} },
    "19": { "tag": "block", "kind": "block", "ty": 1232,
            "data": {"ty": 1232, "payload": 4},
            "payload": {"body_len": 2}, "body": [20, 21] }
  },
  "ip": {                                // closure of every reached InternPool index
    "1231": { "key": {"int_type": {"signedness": "unsigned", "bits": 32}},
              "q": {"zig_type_tag": "int", "has_layout": true, "abi_size": 4, "abi_align": 4} }
  },
  "navs": { "56": { "fqn": "basic.scale", "name": "scale", "module": "root", "file": 3,
                    "resolved": {...}, "forced_val": false } },
  "files": { "3": { "sub_file_path": "basic.zig", "module": "root" } },
  "order": { "types": [1231, 1230, 1232], "globals": [], "externs": [] },
  "uses": { "ptr": { "8812": {"global": {"nav": 77}, "off": 0, "payload_base": false} } }
}
```

`order` records the first-encounter sequences that the traversal produced (they are what the
forcing order depends on); `uses` records answers that depend on when they were asked (the
pointer resolution of a constant, §Forcing points). The renderer re-derives the IDs from its own
traversal and must reproduce `order` exactly: a mismatch is an error, not a different output.

## Renderer

A standalone Zig program (`zig-patch/render/`), built by stock Zig 0.17.0, reads the facts of one
export directory and writes the AIR JSON files (schema 12) to `ZIG_AIR_JSON_DIR`. It owns
everything `json.zig` does after the compiler has answered: the instruction arms, value and type
entries, the type/global/extern tables and their order, the profile object, filenames
(`docs/export-names.md`), existing-file validation, identity claims and their fail-closed exit,
instance keys, the error table and the `@export` rewrite. Planned split: `insts.zig`, `types.zig`,
`values.zig`, `globals.zig`, `identity.zig`, `errors.zig`, `schema.zig`. It fails closed on an
unknown facts schema, kind, tag or key shape.

`scripts/zig-air.sh` will compose the two: its `zig` sets `ZIG_AIR_FACTS_DIR` to a private
directory, runs the capture compiler, then the renderer into `ZIG_AIR_JSON_DIR`. `cas.py` keys the
compiler on hook + capture only, the renderer separately, and caches facts (`facts/`) so a
renderer change re-renders without recompiling anything.

## Equivalence gate

`scripts/exporter-equivalence.py` re-runs every recorded export: the goldens (commands derived
from `examples/` exactly as `scripts/check.sh` does) and the fixtures in
`tests/roadmap/exporter-equivalence/exports.toml` (every key of `scripts/coverage.py`
`COMPILER_FIXTURE_ROOTS` is listed there or excluded with a reason; the unit test checks it). For
each it exports with the current patched compiler and, with `--alt CMD`, with an alternative
exporter command run as a drop-in `zig`, and requires the two output directories to be identical
byte for byte; it also compares the current export with the committed directory (`exact`,
`subset`, or the golden normalization), reporting the normalized comparison when the bytes
differ. `--alt self` checks determinism.

The renderer is accepted when `--alt 'zig-patch/render/zig-air-render {zig}'` (the composed
command) is identical on every export of every version.

Baseline (2026-10-12, `origin/main` 3739b546, aarch64-macos, `--alt self`):

| Version | Exports | Alternative identical | Committed: ok | Committed: differs |
|---|---|---|---|---|
| 0.17.0 | 22 (17 goldens, 5 fixtures) | 22 | 22 | 0 |
| 0.16.0 | 61 (17 goldens, 44 fixtures) | 61 | 49 | 12 |
| 0.15.2 | 34 | 34 | 34 | 0 |
| 0.14.1 | 22 | 22 | 22 | 0 |

The exporter is deterministic on every recorded export. The twelve 0.16.0 differences are
fixtures older than the current exporter, not exporter faults: `thread-tuples`, `spawn-failure`,
`futures` differ in compiler numbering (`__anon_<n>`, `__enum_<n>`) and in type entries;
`thread-locals`, `pointer-width-{wasm32,reject}`, `big-endian-reject` predate the 0.16.0 container
layout forcing (73c8bdb6: their types lack `abi_size`/`fields`/`ptr_align`); the five
`alloc-translated`/`alloc-fba` closures were exported by the P0 exporter. Unfiltered, those five
now stop at the exporter's identity check (`std:debug.ElfFile.searchSymtab.SearchContext` is
declared by two instances), so the manifest re-exports exactly the committed functions
(`filter_from_committed`).

## Computed queries

What `json.zig` and `identity.zig` ask the compiler beyond raw keys, grouped. Each becomes a fixed
capture query, recorded where it is asked.

- **Type shape:** `zigTypeTag`, `intInfo`, `floatBits(target)`, `ptrSize`, `isConstPtr`, `childType`,
  `ptrInfo`, `ptrAlignment`, `arrayLen`, `arrayLenIncludingSentinel`, `sentinel`, `vectorLen`,
  `optionalChild`, `errorUnionSet`, `errorUnionPayload`, `isTuple`, `fnReturnType`, `isFunctionType`.
- **Containers:** `containerLayout`, `structFieldCount`, `structFieldName`, `fieldType`,
  `structFieldIsComptime`, `structFieldOffset`, `enumTagType` (`intTagType`/`backingIntType`),
  `isNonexhaustiveEnum`, `enumFieldCount`, `enumFieldName`, `enumValueFieldIndex` (interns),
  `unionTagType`, `unionTagTypeHypothetical`, `unionSafetyTag` (`tag_usage`/`unionTagTypeSafety`),
  `unionFieldTypeByIndex`, `containerTypeName`, `typeDeclInstAllowGeneratedTag` (module).
- **Layout:** `hasLayout` (`want_layout`/`haveLayout`), `hasFields`, `abiSize`, `abiAlignment`,
  `comptimeOnly`, `optionalReprIsPayload`, `codegen.errUnionPayloadOffset`, `onePossibleValue`
  (0.14.1).
- **Error sets:** `isAnyError`, `errorSetNames`, `funcIesResolvedUnordered`, `errorSetBits`.
- **Values:** `typeOf`, `toBigInt`/`toBigIntSema`, `fmtValue` (text of `val` fallbacks), `elemValue`,
  `fieldValue`, `isUndef`, `toSignedInt`, `Type.fmt` (`"other"` type names).
- **AIR:** `typeOfIndex`, `getMainBody`, `extraData`, `unwrapSwitch` + `iterateCases`, `unwrapAsm`,
  `unwrapShuffleOne`/`Two`, `NullTerminatedString.toSlice` (dbg names).
- **Declarations:** `getNav` (`fqn`, `name`, `resolved`/`status`), `funcInfo`, `funcDeclInfo`,
  `navFileScope`, `navSrcLine`, ZIR declaration linkage, file `sub_file_path` and module,
  `main_mod`/`std_mod`, `comptime_args`, `uncoerced_ty`.
- **Compilation:** `getTarget`, module `resolved_target` (`zigTriple`, `ptrBitWidth`, endian, ABI, CPU
  model and features), `optimize_mode`, `error_tracing`, `zigBackend(use_llvm)`,
  `build_options.version`, `ZIG_AIR_JSON_DIR`/`ZIG_AIR_JSON_FILTER`.
- **Use-site answers:** the resolution of each pointer constant (`resolvePtr`: global and offset,
  `null`, or the `unsupported` reason), which depends on the layouts forced so far.

## Forcing points

Calls that change compiler state while exporting. The capture must make each at the same point.

| # | Where | Call | Versions |
|---|---|---|---|
| F1 | global entry of a non-extern `Nav` without a value | `ensureNavValUpToDate` | all |
| F2 | first type ID of a struct, union or enum | `ensureTypeLayoutUpToDate` (`.field_queried`) | 0.16.0+ |
| F3 | integer constant text | `toBigIntSema` resolves lazy `@sizeOf`/`@alignOf` | 0.14.1, 0.15.2 |
| F4 | `arg` parameter index | `onePossibleValue(pt)` | 0.14.1 |
| F5 | aggregate constant elements, enum field values | `elemValue`/`fieldValue(pt)`, `enumValueFieldIndex` intern | all |
| F6 | `err_trace` type (open #159/#168) | `singleMutPtrType`, `optionalType` intern | all |
| F7 | `navInfo` of a pending global (c-frontend) | `ensureNavValUpToDate` | 0.16.0+ |
| F8 | error table, `@export` symbols (open #172, c-frontend) | none (reads at `analysisDone`) | all |

F1/F2 are the arena branch's exporter delta (73c8bdb6, `ArenaAllocator.init`'s
`heap.ArenaAllocator.Node`, `PageAllocator.vtable`); it is on `main`. F5 and F6 intern new
values: they shift the InternPool indices of everything analysed afterwards.

## Identity and visit-order invariants

The renderer reproduces these from the facts; the equivalence gate checks them.

1. An instruction's `id` is its AIR index; bodies are written in AIR order, nested bodies inline.
2. A type ID is the position of the type's first `writeTypeRef` in write order: function header
   (`params`, `ret`), body (each instruction's `ty`, then its operands and payload refs in field
   order, recursively through constant refs), `externs` entries, the `globals` drain (an entry
   can append globals and types), then the `types` drain (an entry can append types).
3. A global ID is its first encounter in the same order; a pointer constant whose resolution
   fails never allocates one. `externs` are in first-call order.
4. Error set names are sorted bytewise; struct, enum and union fields are in declaration order;
   CPU features in the architecture's feature-list order.
5. Filenames: the storage name (`root`/`std`: the fqn, else `module:fqn`), hashed when unsafe or
   long (`docs/export-names.md`). Output claims span the process; type, global, module and
   instance claims one compilation. A second owner of an identity fails the export.
6. `instance_key`: SHA-256 of the canonical encoding (`air2lean-instance-v1`), cached per
   (compilation, nav).

## Risks

- **Forcing and interning order.** If the capture forces or interns anything `json.zig` does not
  (or in another order), later answers and later `__anon_<n>` names change. Mitigation: the
  capture runs the `json.zig` traversal itself, records `order`, and the gate compares bytes on
  all 139 recorded exports. Forcing everything up front would be simpler but changes outputs
  (`resolvePtr` can ask for a pointee's layout before `json.zig` forces it); that is a separate,
  deliberate format change with refreshed goldens, not part of the cut-over.
- **Facts size.** A std closure is large; facts are per function. Share one InternPool table per
  compilation (`analysis.facts.json`) once the first renderer works.
- **Two trusted programs.** The renderer joins the trusted base that `json.zig` is today. It is
  built by stock 0.17.0 only and fails closed on anything it does not know.
- **Ports remain.** The capture still needs a per-version port (API renames, tag sets), but its
  surface is the tag kinds and the query list; the tag switch is generated and exhaustive.
- **Older versions.** The capture for 0.14.1/0.15.2 may come later than 0.17.0/0.16.0; until it
  exists those versions keep `json.zig` (the cut-over is per version, and the gate is per
  version).
- **Exit semantics.** Identity collisions stop the compiler today (exit 1). After the split the
  renderer stops instead; `zig-air.sh` must return its failure.

## Phases

B0 (this): harness, manifest, classification, tag tables, design. B1: `capture.zig` for 0.17.0,
then 0.16.0, 0.15.2, 0.14.1, built alongside `json.zig` (both hooks active, facts and JSON from one

`cas.py` keys and facts cache, docs. B4: cut-over per version (`json.zig` removed when the last
version is cut over; files move to `exporter/{hook,capture,render}`).
