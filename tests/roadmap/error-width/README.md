# Error-code widths (`--error-limit`, L10)

Zig stores errors as `u<error_set_bits>`, where the width is `log2(--error-limit) + 1` and
16 is the default. The model and translator take the width from the profile
([profiles.md §Error-code width](../../../docs/profiles.md#error-code-width---error-limit)).
This case checks four widths:

| Directory | `--error-limit` | Bits | Code bytes | `E!u8` | Evidence |
| --- | --- | --- | --- | --- | --- |
| `air/bits16` | 65534 (default) | 16 | 2 | 4 bytes, code first | Hand-written fixture; the existing native gate ([error-storage](../error-storage/README.md)) |
| `air/bits8` | 255 | 8 | 1 | 2 bytes, payload first | Hand-written fixture |
| `air/bits10` | 1000 | 10 | 2 | 4 bytes | Hand-written fixture |
| `air/bits17` | 100000 | 17 | 4 | 8 bytes | Hand-written fixture |
| `air-fresh/<version>/bits{2,8,10,16,17,32}` | 3, 255, 1000, default, 100000, 4294967295 | 2 to 32 | 1, 1, 2, 2, 4, 4 | 2, 2, 4, 4, 8, 8 bytes | Compiler exports of `error_width.zig` by the patched 0.16.0, 0.15.2 and 0.14.1 (`export.sh`) |
| `native/<target>-<version>.txt` | 22 configurations (`native.py`) | 1 to 32 | | | Stock-compiler observations compared with the model (`Model.lean`) |

## Compiler exports

`air/` is hand-written: `make-fixtures.py` writes it from `error_width.zig`'s shape using Zig
0.16's layout rules. `air-fresh/` is real: `export.sh` runs the patched compilers built by
`zig-patch/build.sh` from this tree (their hashes are pinned in `provenance.json`;
`export.sh --check` refuses another build) on `error_width.zig` with `--error-limit` 3, 255, 1000,
the default, 100000 and 4294967295, for each of the three versions. The exporter's profile carries
the width (`error_set_bits`). Every export is translated, elaborated and executed by the same
checks as the hand-written fixtures (`RunCommon.lean`, `RuntimeExport.lean` generated by
`check.sh`). The real exports use other lowerings than the hand-written ones (for example the
whole-union store of `errunion_payload_ptr_set`), so they are separate evidence, not a diff
target. `test_provenance.py` checks the hashes and that every file is the profile it claims.

## Native observations

`probe.zig` is built by `native.py` with a stock `zig build-exe -lc -OReleaseSafe
-fno-error-tracing [--error-limit N]` for 22 configurations, each a limit and the number of errors
the compilation names (`errs.zig`, generated: `Failure` plus extra errors to reach the total). It
uses no `std` beyond `std.debug.no_panic`, because `std` alone names hundreds of errors. It prints:

* the width (`@bitSizeOf(anyerror)`), size, alignment and number of defined bytes of the error
  integer, and the same for `?E`;
* byte-image properties: a stored error is a nonzero code, two errors differ, the image of an error
  is the little-endian bytes of `@intFromError`, `null` is the zero code, `?E` shares the image of
  `E`, and `@errorFromInt(@intFromError(e)) == e`;
* for seven payloads, `E!T` size, alignment, and the offsets of the code and the payload, found by
  placing a code, or a payload, at every offset of zeroed memory and reading the memory as the
  union;
* `@errorFromInt` bounds, one `probe from C` process per integer: 0, the error count N, N + 1,
  `2^bits - 1` and `2^bits` (panics are signal exits), and the names of codes 1..N (the first and
  last three above 1000 errors).

The limits are 1, 2, 3, 4, 7, 8, 255, 256, 1000, the default 65534, 65535, 65536, 100000, 2^23,
2^24, 2^31 - 1 and 2^32 - 1. Most compile exactly as many errors as the limit allows (up to 65536;
70000 for limit 100000; 5 for the widest limits). Limits 1, 2 and 255 are also tried with one error
more, and limit 0 with two: none of these compile. `Model.lean` recomputes every line from `ZigLean/Mem/ErrWidth.lean` and
definitions and compares it with the recorded file
(`native/aarch64-macos-<version>.txt`, recorded on Apple M1; the x86_64-linux run is
`AIR2LEAN_ZIG_NATIVE=<stock zig> bash check.sh`). The compiler's numbering is a parameter: the
model checks that it is a table of the width (`ErrorTable.check`), that the casts invert each other
and where they panic, not which number an error gets.

Results, with 0.15.2 and 0.16.0 identical:

* Width = `bit_length(limit)`; size and alignment are 1, 2 or 4 bytes; `E!T` layout, `?E` and
  `null`, the casts and their bounds all match the model, from 1 bit (limit 1) to 32.
* The model differs on the number of defined code bytes at 17 to 24 bits (limits 65536, 100000,
  2^23): a store of the error integer writes `ceil(bits / 8)` bytes, so the fourth byte of a 4-byte
  code is padding; the model fills all `errCodeSize` bytes (`enc defined 4` against `3`). The
  model writes a fragment into that byte and its decoder requires it, so it is stricter than the
  native layout when reading (it rejects a code natively written without the padding byte) and
  more defined when writing; translated programs only read what they wrote, so no program is
  mis-modelled, but the correspondence of the fourth byte is not established. Listed in
  `native/expected-mismatches-<version>.txt`.
* 0.14.1 names 12 errors in its start code, so no compilation has fewer than 13, and widths below
  4 bits are not observable (`skipped`). It also mishandles codes of width `bits` with the top bit
  set: `@errorName` of such a code is empty, and `@errorFromInt` rejects codes above 253 (limit
  255), 32767 (limits 65534 and 65535) or 65535 (limits 65536 and 100000) although the errors
  exist. The model has no such rule (`bound count N`). Listed in
  `native/expected-mismatches-0.14.1.txt`; these are the failing expectations for 0.14.1, not a
  model change.

A recorded mismatch must not change silently: `Model.lean` fails on a mismatch that is not listed
and on a listed one that no longer occurs. `check.sh` also runs five mutated observations (payload
offset, code size, `@errorFromInt` bound, zero code, compile verdict), which it must reject.

`check.sh` runs these steps:

1. Checks that the committed fixtures are current (`make-fixtures.py check`).
2. Translates each width and compares the output byte-for-byte with `expected/ErrorWidth<N>.lean`,
   then elaborates it.
3. Checks that the 16-bit output uses the original 2-byte operations (no `…W 16`) and that the
   other widths use `…W <bits>`.
4. Runs `Runtime.lean`, which executes every generated function with each width's own
   dictionaries. Errors, `null`, success payloads and the zero code written by
   `errunion_payload_ptr_set` all survive. A foreign name and a narrower code do not reload
   as members.
5. Runs `negatives.py`, which requires rejection of width 0, width 33, a profile/layout
   disagreement in either direction, a domain wider than the width (`--error-limit 1`) and a
   program that mixes widths.
6. Checks `provenance.json` (`test_provenance.py`), then translates, elaborates and executes the
   18 compiler exports of `air-fresh/` with the same checks as step 4.
7. Compares the three recorded native observations with the model (`Model.lean`), and five mutated
   observations that must be rejected. With `AIR2LEAN_ZIG_NATIVE=<stock zig>` it also records this
   host's observation (`native.py`) and compares that.

The universal statements (store/load, wrap/unwrap, code slices, integer/error casts and
out-of-range codes, for every width from 1 to 32 bits) are in `ZigLean/Mem/ErrWidthLemmas.lean`.

```sh
lake build ZigLean ZigLean.Mem.ErrWidthLemmas Air2Lean air2lean
bash tests/roadmap/error-width/check.sh
# Re-record, with the compilers named in provenance.json (zig-patch/build.sh builds the patched ones):
AIR2LEAN_ZIG_AIR=<dir with zig-air-<version>/bin/zig> bash tests/roadmap/error-width/export.sh --check
python3 tests/roadmap/error-width/native.py <stock zig> native/<target>-<version>.txt
python3 tests/roadmap/error-width/test_provenance.py --refresh
```

`AIR2LEAN_ERROR_WIDTH_UPDATE=1` rewrites `expected/` after a deliberate emitter change.
Integer/error casts remain rejected by the translator. Their semantics are stated over an
explicit compilation numbering (`ErrorTable`), which AIR does not export.
