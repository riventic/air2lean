title: Unspecified float cases
status: complete
row: Completed (close-out review 2026-11-26): [PR122](https://github.com/riventic/air2lean/pull/122): ZigLean/Float/Allowed.lean: `Float.Allowed` (the exact result, or any NaN when the model's result is a NaN), `MinAllowed`/`MaxAllowed` for the signed-zero (group D) and signaling-NaN (group I) @min/@max cases in every format, and the lifted `AllowedSpec`; the model is sound for the relation (`Allowed.refl`, `min_allowed`, `max_allowed`, `minChk_allowed`), classification, comparisons and `add`/`mul`/`div`/`sqrt`/unguarded `conv` are payload-independent (`classify_eq`, `lt_eq`, `add_eq`, …), and `@intFromFloat` errors stay errors on every allowed operand (`toInt_allowed`: overflow stays `.overflow`, a NaN of any payload `.illegal`); clients `isNan_allowed`, `clamp_allowed` (Proofs/Floats) and `toByte_allowed`, `toByte_allowed_overflow`, `toByte_allowed_nan` (Proofs/Floatconv), whose `Gen.lean` is the translation for every Zig version (`scripts/check.sh`). A NaN's bits are never observable in the model (`Float.detMask`, `docs/architecture-audit/nan-bits.md`, `tests/roadmap/nan-bits` on 0.14.1–0.17.1), so no proof can depend on a payload. Negative tests `nan_varies`, `min_zero_varies`, `toInt_allowed_nan` (Proofs/Floats/AllowedNeg.lean) kill mutate.sh `ag`/`ah`, which collapse the relation to the model's result. Scope: generated code calls the deterministic model; the relation is for proofs. Target-specific helper behaviour is exact per target and `--float-semantics` mode and labelled per theorem (`assurance/float-semantics.json`), not an allowed set; the bit-reading group C guards (f128→f80 `convChk`, f80 `Chk`) are `.unspecified` on a non-canonical NaN (fail closed), so an `AllowedSpec` over them is not provable. Target-exact NaN payloads are not modelled, since Zig leaves them open; transcendental results are F02.

Bounded progress ([PR122](https://github.com/riventic/air2lean/pull/122)): ZigLean/Float/Allowed.lean: `Float.Allowed` (the exact result, or any NaN when the model's result is a NaN), `MinAllowed`/`MaxAllowed` for the f32/f64 signed-zero @min/@max case and the lifted `AllowedSpec`; the model is sound for the relation, classification/comparisons/arithmetic are payload-independent, and @intFromFloat errors stay errors on every allowed operand; clients in Proofs/Floats (isNan, clamp) and Proofs/Floatconv (toByte).

Completed (close-out review 2026-11-26): useful proofs tolerate the permitted variation: `isNan_allowed`, `clamp_allowed` and `toByte_allowed*` hold for every result `Float.Allowed`/`MinAllowed` admits. They do not pretend to know NaN payloads: a NaN's bits are unobservable in the model (`Float.detMask`; `@bitCast` of a NaN is `.unspecified`), and `nan_varies` shows the relation admits another NaN. Invalid inputs stay explicit: `Float.toInt_allowed` and `toInt_allowed_nan` keep `@intFromFloat` of a NaN `.illegal` and out-of-range values `.overflow` for every allowed operand. Mutants `ag`/`ah` are killed by `Proofs.Floats.AllowedNeg`. Scope: the relation is for proofs, while generated code keeps the deterministic model. Target helper behaviour is exact per target and mode and labelled (`assurance/float-semantics.json`). Group C bit-reading guards fail closed. Target-exact NaN payloads are not modelled.
