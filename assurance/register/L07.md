title: Aggregate and optional-pointer bitcasts
status: partial
row: Existing dedicated packed/optional conversions. [PR125](https://github.com/riventic/air2lean/pull/125): Zig ≤0.16 representation `@bitCast` of arrays, `extern` structs and `extern` unions (`Zig.reprCast`: encode, pad, decode; padding and unused bits undefined, so a result that needs them is `.unspecified`), with checked equal `@bitSizeOf` and a version gate (0.17+ and unversioned contexts reject); pointer-bearing repr casts are rejected (pointers and optional pointers at any depth, fail closed); `?*T` unwrap (null panics), `@intFromPtr`/`@ptrFromInt` null rules; proof-only `ZigLean.ReprCast` (round trip under the stated no-padding condition, undefined-byte throws); hand-written fixture and an aarch64-macos native probe whose defined bytes match the model. [PR135](https://github.com/riventic/air2lean/pull/135): compiler-exported fixtures for the casts: `aggregate_casts.zig` exported by patched 0.16.0, 0.15.2 and 0.14.1 compilers (`air/<version>`, pinned by `provenance.json`); the real compiler also emits the `@ptrFromInt` alignment check and the `?*T` unwrap null check, so the proofs now cover the misaligned `@ptrFromInt` panic and wrap/unwrap of a nonzero-address pointer; the earlier hand-written AIR stays as `air-handwritten`; the 0.15.2 and 0.14.1 translations equal the 0.16.0 one apart from the profile header. Batch D (PR "Roadmap batch D: L08 L07 T03 L04"): one representation class for packed fields and casts (`Zig.Packed` with a determined-bit `mask`; `ZigLean/PackedRepr.lean`: floats, packed unions, arrays, vectors); a Zig 0.17 `@bitCast` of every type with a logical bit representation the model has (nested arrays, arrays and vectors of floats, enums, packed structs and unions, packed unions) is `Packed.toBits?` then `ofBits?` (NaN bits `.unspecified`, an unnamed enum item `.illegal`); packed unions in ≤0.16 representation casts and packed struct/union ↔ packed/float/`bool` casts in every version; arrays of `auto` structs and tagged unions as memory reinterpretations on 0.14.1/0.15.2 (Sema checks only the outer type there); casts of `auto` structs, tuples and tagged unions are compile errors in every version (`compile-errors/`, per-version expectations); `Packed.bitCast_roundtrip` states the round-trip condition; `tests/roadmap/packed-casts`: exports by 0.14.1-0.17.1, kernel-checked results, native x86_64-linux outputs equal to the model's. L07 remaining casts (branch `claude/l07-casts`): a sentinel-terminated array in a ≤0.16 cast is the same memory reinterpretation with the sentinel as one more item (`reprBitSize` counts it as Zig's `lenIncludingSentinel` does; `sentinel_arrays.zig` exported by 0.14.1-0.16.0, kernel-checked results, native x86_64-linux, aarch64-linux and aarch64-macos outputs equal to the model's; 0.14.1 leaves the sentinel of a runtime array initialization unwritten, which is undefined in the model too); zero-bit casts have a rule in both semantics (`Zig.Packed Unit 0`, `reprBitSize` 0 for `void`; Sema folds every such cast, so the source casts are exported for 0.14.1-0.17.1 and the instruction is tested from hand-written AIR); named rejections, each with a test (`reject/expected.txt`): a sentinel array in a 0.17 cast (Zig 0.17.1's comptime evaluation, LLVM backend and self-hosted x86_64 backend give three different results, `docs/upstream/bitcast-sentinel-array.md`), arrays of tuples, of error sets or error unions and of optionals in 0.14.1/0.15.2 casts (compile errors from 0.16.0, `compile-errors/`), a sentinel array ↔ vector up to 0.16, `void` itself before 0.17; `expected/wrong.txt`: the results of wrong models (sentinel left out, sentinel forced to the type's, `void` with bits) fail the comparison with the model and with the native output. Optionals as array items (branch `claude/l07-opt`): on 0.14.1/0.15.2 an array of non-pointer optionals is a memory reinterpretation (`reprBitSize`: an optional item's bits are its ABI size, its payload any item type, its flag offset pinned by the exporter's payload and optional layouts; `Enc (Option α)`); `opt_items.zig` covers integer payloads (`u0`, `u12`, `u24`, `i8`, `u8` to `u128`), `bool`, `f16` to `f128`, an enum, arrays, nested optionals, `extern`, packed and `auto` structs and a vector, with kernel-checked results and native x86_64-linux (LLVM and self-hosted backends, ReleaseSafe and Debug) and aarch64-macos outputs equal to the model's; nested arrays of optionals are compile errors from 0.16.0 (`compile-errors/`); a representation cast decodes with the profile's storage encodings (the self-hosted x86_64 backend reads a `u24` payload's padding byte as part of the value, so its profile's model says `.unspecified` there: `opt_items_x64`), and a padded integer in one is rejected on a profile that names no backend; a flag byte other than 0 or 1 is `.illegal` (conservative: native code reads it as non-null); optionals of tuples, errors or pointers stay rejected (`reject_items.zig`); `expected/wrong.txt` adds wrong optional layouts (flag first, flag after the padding, no `?u0` flag, one shared `??u8` flag). Remaining: arrays of tuples and optionals of tuples (0.14.1/0.15.2: the memory model has no tuple layout), error storage as array items or optional payloads (0.14.1/0.15.2: the model's error bytes are symbolic, not the compilation's error codes), a sentinel array in a 0.17 cast (upstream bug: comptime evaluation, the LLVM backend and the self-hosted x86_64 backend give three different results, `docs/upstream/bitcast-sentinel-array.md`; maintainer decision), and a check of a cast result's last item against the type's sentinel (the export has no array sentinel value; the compilers do not check it either).
---
representation-based casts for arrays, structs, tuples and qualified unions, including padding/undefined bits. Extend optional-pointer conversions with explicit wrapping/unwrapping rules. Acceptance: round trips hold only under stated representation conditions; tests include padding and null values.
