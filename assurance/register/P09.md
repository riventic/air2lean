row: Approved by the maintainer as part of the end state (2026-10-14); design in docs/invariant-synthesis.md. A module proof states only its specification (the generic contract instantiated, the request bound `fits`, the creation triple's precondition); an offline, untrusted generator (`air2lean-invgen`, no tactic, no judgment) writes the implementation's invariant, loop invariants, measures and range facts as ordinary definitions into a committed `Inv.lean`, and `fsym` and the kernel check them. Layers, cheapest first: data-structure predicates from the translated types, numeric facts and measures (intervals, octagons, congruences pruned Houdini-style by `fsym`), ghost and ledger invariants from generic library families, and a fallback of committed hints. A creation triple with an `FAdmit` companion is mandatory, because a kernel-checked invariant can be vacuous (tests/roadmap/invariant-synthesis/Vacuity.lean). First generator slice (S2, counted loops): `air2lean-invgen` generates the inner loop invariant and measure of tests/roadmap/loop-tactics/nested (`Nested/Inv.lean`, regenerated by the `invgen` step of scripts/regen.py and checked byte for byte and against seeded mutants by its check.sh; its record's generator revision and input hashes checked without Lean by `scripts/gen-integrity.py invgen`). S2c widened the counted family (counters going down, `!=`, `<=` and `>=` tests, slice-length and read-only-cell bounds) with tests/roadmap/loop-tactics/counted as client: five translated Zig 0.17 loops proved with generated invariants only, each with a seeded mutant that fails; since S2c′ (2026-11-25) the family also covers items of an array parameter (`arr p (w₀ :: … :: t)`, `counted.pairAt`), a cell that goes up by a value of the counter (over the library sum `tsum`, `counted.tri`) and a body that runs an inner counted loop, read as the inner loop's exit post (`nested`'s outer loop: its hand `outerI`, `outerPost`, `outer_step` and `outer_loop` are deleted, `pairs_total` is a bare `fsym`, ledger P09-E4 closed), each with seeded mutants that fail. S2f prunes Houdini-style: the generator walks each loop's step triple over its candidate facts with `fsym` (`Auto.runReport` via `fsym.report`, in its own environment), drops the candidates the report names as residuals until a walk proves the step, and records every pruning decision in `Inv.lean`'s record; two seeded mutants (a pruned candidate kept, a kept one dropped) fail. P09-E4: the generated invariants, measures and exit posts are registered with `@[fsym_inv]`, so the callers' walks are bare `fsym` with no loop lemma. S2d, the list-walk family: the walks of `Proofs/Lists` have generated invariants over the library list family `listSeg` (`Proofs/Lists/OpenInv.lean`: `reverse`, `sum`), and a walk that hands each node to a call has one read off the call's contract (`--spec`/`--contract`; `Proofs/Lists/AllocInv.lean`: `freeAll`, whose hand step and loop lemmas are deleted); The credit mode (maintainer decision 2026-11-24): `@[fsym_inv]` takes a second invariant per loop body selected by the walk's mode (`B.credits.inv`, `B.credits.post`, at the exact count of the body runs left), `fsym` takes it with the counted loop rule when the state at the loop holds credits and no plain mode, never the plain-mode one, and the generator derives it from the plain-mode invariant for every family (checked by a walk of the counted rule's step); `sum_exact` and `freeAll_exact` are proved over them and their hand invariants and step and loop lemmas are deleted. S2b (2026-11-25): each loop's entry in the record names its function and that function's semantic fingerprint (from a source map of the committed AIR, without the translator and runtime revisions), checked by `scripts/gen-integrity.py invgen`, and `scripts/invgen.py check` names the functions whose fingerprints changed. Retranslation (2026-11-26): every client has variants (`scripts/invgen.py` `VARIANTS`: the counted and nested loops by Zig 0.14.1, 0.15.2, 0.16.0 and 0.17.1, the linked list of Proofs/Lists by the same four and with the fields of `Node` permuted), each another translation under the first one's module names with its own regenerated `Inv.lean`; tests/roadmap/loop-tactics/check-variants.sh checks both regenerations, elaborates the one set of hand-written specifications and proofs against each variant unchanged and requires the seeded mutants to fail there. A permutation that changes the layout (`Node` an `extern struct`: `next` at offset 8) is followed by the generator (a node layout with no field at offset 0 states `0 ≤ p.off`; before, `reverse.loop6` got no invariant) but not by the hand-written files, which state the node's layout by offsets (`Linked.node`, `AllocNode.nodeRest`, `Alloc.nodeBytes`): the check pins that they are rejected for it. Open for this acceptance sentence: specifications that state a node through the translated struct type (the struct atoms of S3), and loop names that do not carry AIR instruction indices (`sum.loop6`, `freeAll.loop5.done` in hand-written statements; a translator decision). Next: the arena and FBA invariants (S3, S4) (docs/invariant-synthesis.md).

Generate implementation invariants, loop invariants, measures and range bounds from the
specification, so that a module proof supplies only its contract instance. The generator is
untrusted: `fsym` and the Lean kernel check everything, a candidate that does not check is
reported with its residual goals, and the build fails closed. No new judgment or tactic: the
generator is an offline program whose output is ordinary definitions in a committed,
reproducible file (like `Gen.lean`), consumed through `fsym` registries (`@[fsym_inv]` loop
invariants, `@[fsym_upd]` library ghost updates; engine rows P09-E1 to P09-E5 in
docs/invariant-synthesis.md).

Acceptance (docs/invariant-synthesis.md, "Acceptance"):

- The translated `FixedBufferAllocator` (with its reset ledger) is proved with a generated
  invariant and no hints: at most 60 hand-written lines (statements, `fits`, the creation
  triple), no module-specific lemma, every proof `fsym` with no module lemma arguments, and an
  `FAdmit` companion for the creation precondition.
- The translated `ArenaAllocator` is proved with generated invariants: `AllocArena/Core.lean`
  shrinks to the specification instance (at most 150 lines, no module-specific lemma; 95 today),
  `AllocArena/Reset.lean` is deleted, `ArenaSpec*.lean` hold statements only (at most 40 lines
  each, no hand loop invariant), and the 11 arena tactic macros and `arena_spec_statements` are
  deleted with their 12 entries in `assurance/proof-framework.json`. A creation triple with its
  companion is added.
- The list and queue loops (`Proofs/Lists/Linked.lean`, `Proofs/Lists/Alloc.lean`'s `freeAll`)
  use generated invariants and measures, and `tests/roadmap/loop-tactics/Queue.lean` builds
  unchanged.
- Retranslation for another Zig version or with permuted struct fields needs regeneration only;
  seeded mutants of the entries get no checking invariant; `scripts/regen.sh` reproduces every
  `Inv.lean` byte for byte with the network disabled.
