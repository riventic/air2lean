verify C programs through stock `zig translate-c` and the existing Zig route; state the trust added by translate-c and the libc headers. Acceptance: every corpus file is translated and `#guard`-checked or rejected by a named, documented gate; every libc symbol the corpus calls is translated from pinned real code or a trusted-base model with a stated contract; known compiler bugs are gated or avoided by a qualified Zig version; the heavy coverage run is reproducible and CI checks its record (docs/c-frontend.md).

Baseline ([PR129](https://github.com/riventic/air2lean/pull/129), Zig 0.16.0): corpus, harness, generator and committed records; 17/40 corpus files and 30/30 generated programs are `lean_ok`.

Zig 0.17.1: 28/41 corpus files and 30/30 generated programs are `lean_ok`; 10 files are rejected by a named gate (docs/c-frontend.md §Gates). The harness closes the AIR export over std callees, runs the translator with `--allocator-model translated`, and can defer Lean elaboration to a build host; the translator models Zig 0.17.1's array `splat`, its `int_from_ptr`/`ptr_cast` of an optional pointer (`casts`) and its `array_to_vector` coercion (`[n]T`, sentinel or not, → `@Vector(n, T)` lane-wise for every lane type; `tests/roadmap/zig017/tovec` agrees with native aarch64-macos and x86_64-linux on 420 vectors), so `strchr` (`std.mem.findScalarPos`) translates.

libc binding (maintainer decision 2026-11-24): the AIR is exported from the compilation that `zig build-exe -target x86_64-linux-musl -lc` makes, which holds Zig's libc (`lib/c.zig`) as its module `zigc`; the exporter writes the compilation's `@export` records (`export-table.air2lean`, Zig 0.17.1); the export closure follows a called symbol to its defining function; the translator binds the call to the symbol's one definition in the program, a weak one only with `--assume-weak-exports` (premise EXT-07: the image links no other definition of the symbol; recorded in the header). Bound and `#guard`-checked against the C program: `isdigit`, `isalpha`, `isspace`, `toupper`, `tolower`, `abs`, `labs` (`libc_ctype`).

C-ABI conversion (maintainer decision 2026-11-25): where translate-c's declaration and Zig's definition type a pointer differently as the C ABI allows (`[*c]const u8` for `[*:0]const c_char`, `?*anyopaque` for `?[*]align(16) u8`), the value is converted once at the bound call by the cast rules (L07; `ZigLean/Mem/Abi.lean`, agreement lemmas with `ptrRequireNonNull`, `checkAlign` and `ptrToOptional`; full-state rules in `ZigLean/Sep/Full/Abi.lean`): null into a non-optional pointer, a value misaligned for the target and a missing sentinel byte are `.illegal` (the sentinel test is a documented conservative over-approximation). Function pointers, sentinels without an exported byte value (`wcschr`), non-pointer differences, address-taken callees and a function that also calls the definition directly stay rejected (`CALLEE_EXTERN_UNBOUND`/`CALLEE_AMBIGUOUS`). `tests/roadmap/extern-abi` evaluates translate-c output against Zig 0.17.1's libc (`strcmp`, `strrchr`, `memrchr`, `malloc_usable_size`) to the native results and to `.illegal` for each case, and checks the rejected pairs.

Remaining: `libc_string` and `malloc_vec` (docs/c-frontend.md §libc boundary): (1) `qsort`'s definition fails normalization; (2) `memcpy`, `memset`, `memcmp`, `strlen` are `compiler_rt`'s, a separate ReleaseFast compilation, and a program of two build profiles is rejected (`libc_string`'s only remaining reason); (3) `lib/c/malloc.zig` passes an `undefined` context pointer, sits on `std.heap.SmpAllocator` (an `unordered` load in `atomic.Mutex.unlock`) and, with libc linked, on musl's C `mmap`/`munmap`/`mremap`/`__errno_location`, and OSM-01 is not qualified for Zig 0.17.1. `ptr_arith` (a signed item offset for `[*c]` pointers in the memory model, L05); the gated files stay rejected until translate-c translates `goto` (L03), bitfields, variadic definitions and nested case labels, and until its `u1` comparator arithmetic is fixed upstream.
