id: L09
title: Vector memory layouts
status: partial
row: [PR122](https://github.com/riventic/air2lean/pull/122): bit-packed `@Vector(n, uW/iW/fW)` memory layout as the LLVM backend lays it out (`Vec.packedEnc`); ZigLean/VecMem.lean proves the integer round trip at any width, LawfulEnc of the packed encodings and lane-write frames on lanes, on the image and through memory; the checker admits non-byte or ABI-padded lanes only for stage2_llvm profiles; stock Zig 0.16.0 probe images (aarch64-macos, CI x86_64-linux) match the model line for line. [PR124](https://github.com/riventic/air2lean/pull/124) (soundness fix): the exporter writes `vector_index` (lane, "runtime" or null) for every bit-pointer and the checker rejects lane pointers wherever they appear, accepting a field-less bit-pointer only as a packed `struct_field_ptr` result. [PR128](https://github.com/riventic/air2lean/pull/128): lane pointers `&v[i]` into bit-packed vectors of integer or `bool` lanes (`u3`, `u9`, `u24`, `bool`) are bit-pointers into the vector's integer (`lanePtrLayout`, `Zig.loadLane`/`Zig.storeLane`); ZigLean/VecMem.lean proves lane reads, host-only lane writes and `Vec.set` round trips for every width, count and lane; `Lanes/Proofs.lean` proves translated get/put/flip clients; `lanes.zig` passes natively and the probe matches the model on aarch64-macos and x86_64-linux; atomics and `undefined` stores through lane pointers are rejected. [codex/lang-long-tail](https://github.com/riventic/air2lean/tree/codex/lang-long-tail): Zig ≤0.16 vector `@bitCast`: `[n]T` ↔ `@Vector(n, T)` is lane `i` = item `i` (also padded items), every other vector cast reinterprets the bit-packed memory image (`Zig.reprCast`; `ZigLean/VecCast.lean` proves vector → integer, integer → vector and the round trip for every lane width); this unblocks `std.mem.eql` on more than 16 bytes (`mem.eqlBytes`); compiler exports of `vector_casts.zig` with `mem.eql`/`mem.eqlBytes` for 0.14.1–0.17.1 (0.17.1 by its logical bit order), per-version retained translations, proofs on the generated casts, native probes of every version equal to the model, negative tests (non-byte source items, unequal bit sizes, non-LLVM non-byte lanes) and two killed mutants (`tests/roadmap/lang-long-tail`). [PR172](https://github.com/riventic/air2lean/pull/172): `f80` lanes: a lane pointer into `@Vector(n, f80)` is a bit-pointer on the lane's 80 bits (`Zig.Packed (Float fmt)`, `laneBits?` for floats), translated for 0.14.1–0.16.0 (`float_lanes.zig`, native probes equal to the model); Zig 0.14.1/0.15.2 runtime-index lane stores: the exporter writes `vector_store_elem`'s operands, `Canon.dropDeadRuntimeLanePtrs` drops the unread runtime lane pointer before it, and the store is the store through the lane pointer of lane `i` (`Zig.storeLaneAt`; `storeLaneAt_lt`/`storeLaneAt_ge` in `ZigLean/VecMem.lean`; `runtime_lanes.zig` with `u9`, `u24`, `bool` and `f80` vectors and a local filled at runtime indices, native probes of both versions equal to the model, `ProofsRuntimeLanes.lean`: in-bounds stores are lane stores, out-of-bounds is the `outOfBounds` panic); negative tests (another backend, a read runtime lane pointer) and two killed mutants (`tests/roadmap/lang-long-tail`). [claude/l09-lanes](https://github.com/riventic/air2lean/tree/claude/l09-lanes): Zig 0.17.1 lane pointers. 0.17.1 writes `&v[i]` as a `ptr_cast` of the vector pointer to the lane pointer type for every lane type (the exporter already wrote `vector_index`); `Canon.laneElemPtrs` gives it 0.16.0's `ptr_elem_ptr` with the lane index, so the one rule of the other versions (`CheckCtx.lanePtr`, `Zig.loadLane`/`Zig.storeLane`) translates integer, `bool` and `f80` lanes; the predicate `wholeByteLane` splits the element-pointer model (whole power-of-two-byte lanes) from the bit-pointer model, so no lane pointer has both; `lane_shapes.zig` (0.14.1–0.17.1, native probes of the four stock compilers equal to the model, mutant `lane_constant_offset` killed) has a `u9` lane pointer as a constant, a function result, a struct field, into a vector field and `const`. Evidence: stock 0.17.1 passes `lanes.zig` and `lane_reads.zig` and prints the model's `probe.zig` lines in three build modes on x86_64-linux, aarch64-macos and aarch64-linux (except `f80x2` on aarch64, the declared divergence: 0.17.1 lays an `f80` vector out at the array stride there, and the layout comparison rejects it, `float_lanes_aarch64.reject`); committed 0.17.1 exports of `lanes.zig`, `lane_reads.zig` and `float_lanes.zig` translate to 0.16.0's lane accesses, the `Lanes` theorems and the kernel-checked native runs hold on the 0.17.1 translation, and the `float_lanes` native probe of 0.17.1 equals the model; negative tests (another backend, a lane count or lane that is not the vector's, runtime-index and byte-strided forms in 0.17.1's tags). [claude/l09-next](https://github.com/riventic/air2lean/tree/claude/l09-next) (soundness fix): the pointer type decides the lane model. Zig 0.17.1 gives `&v[i]` of a whole-byte lane (`u8`, `u32`, `f64`) the lane pointer type too (the vector's address, `@intFromPtr(&v[1]) == @intFromPtr(v)`; it does not coerce to `*u32`), where the translator had made it 0.16.0's element pointer (the lane's address: `@intFromPtr(&v[1]) - @intFromPtr(&v[0])` of a `u32` vector was 4 in the model, 0 natively) and rejected it as a value; every lane pointer type is now the bit-pointer into the vector's integer and a plain `*T` the element pointer (`wholeByteLane` removed); `lane_values.zig` (0.14.1–0.17.1, native probes of the four stock compilers equal to the model) has `u8`, `i16`, `u32`, `u64`, `u128`, `f32` and `f64` lane pointers as a parameter, a result, a struct field, a `const` lane and a constant, and the address offset (0 in 0.17.1, the lane's size up to 0.16.0). [PR881](https://github.com/riventic/air2lean/pull/881): element-stride layout, library and evidence only (no translator change): `ZigLean/VecStride.lean` has `Vec.stridedEnc` (the array image of the lanes plus tail padding, for every lane encoding, count, size and alignment) and the self-hosted x86_64 backend's size and alignment at the baseline CPU (`x86VecSize`/`x86VecAlign`; `bool` vectors `x86BoolVecSize`/`x86BoolVecAlign`); it proves the round trip (`Vec.stridedEnc_lawful`; floats without a NaN lane), that lane `i`'s cell is the lane's image (`Vec.stridedEnc_cell`) and that a lane store at its cell leaves exactly the image of `Vec.set` (`Vec.stridedEnc_set`); `probe_strided.zig` (812 layouts, 16 vector images around lane stores) printed the model's 910 lines (`ModelStrided.lean`) byte for byte with the stock compilers of Zig 0.14.1–0.17.1, `-fno-llvm`, Debug and ReleaseSafe, on x86_64-linux (a Rosetta container). Remaining: (1) translator admission of the element-stride layout for `stage2_x86_64` (`Check.lean`'s `modelLayout` and lane-pointer checks, `normalize`'s lane pointers, `Emit.lean`'s choice of the encoding), then `bool` vectors above 64 lanes, AVX CPUs and the C backend (no probe yet); (2) other LLVM targets: big-endian (s390x, mips64: `checkBigEndian` rejects non-byte-multiple and `bool` lanes; no native lane-order probe) and wasm32 (`modelLayout` rejects every vector in memory), with their 0.17.1 lane pointers (maintainer decision pending); (3) `f80` vectors in memory on aarch64 with 0.17.1 (array stride at alignment 8; the scalar `f80` alignment differs there too, `docs/aarch64-abi.md`); (4) legacy schema-11 files name no backend and stay rejected (fail closed).
