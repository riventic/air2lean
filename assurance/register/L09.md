id: L09
title: Vector memory layouts
status: partial
row: [PR122](https://github.com/riventic/air2lean/pull/122): bit-packed `@Vector(n, uW/iW/fW)` memory layout as the LLVM backend lays it out (`Vec.packedEnc`); ZigLean/VecMem.lean proves the integer round trip at any width, LawfulEnc of the packed encodings and lane-write frames on lanes, on the image and through memory; the checker admits non-byte or ABI-padded lanes only for stage2_llvm profiles; stock Zig 0.16.0 probe images (aarch64-macos, CI x86_64-linux) match the model line for line. [PR124](https://github.com/riventic/air2lean/pull/124) (soundness fix): the exporter writes `vector_index` (lane, "runtime" or null) for every bit-pointer and the checker rejects lane pointers wherever they appear, accepting a field-less bit-pointer only as a packed `struct_field_ptr` result. [PR128](https://github.com/riventic/air2lean/pull/128): lane pointers `&v[i]` into bit-packed vectors of integer or `bool` lanes (`u3`, `u9`, `u24`, `bool`) are bit-pointers into the vector's integer (`lanePtrLayout`, `Zig.loadLane`/`Zig.storeLane`); ZigLean/VecMem.lean proves lane reads, host-only lane writes and `Vec.set` round trips for every width, count and lane; `Lanes/Proofs.lean` proves translated get/put/flip clients; `lanes.zig` passes natively and the probe matches the model on aarch64-macos and x86_64-linux; atomics and `undefined` stores through lane pointers are rejected. [codex/lang-long-tail](https://github.com/riventic/air2lean/tree/codex/lang-long-tail): Zig ≤0.16 vector `@bitCast`: `[n]T` ↔ `@Vector(n, T)` is lane `i` = item `i` (also padded items), every other vector cast reinterprets the bit-packed memory image (`Zig.reprCast`; `ZigLean/VecCast.lean` proves vector → integer, integer → vector and the round trip for every lane width); this unblocks `std.mem.eql` on more than 16 bytes (`mem.eqlBytes`); compiler exports of `vector_casts.zig` with `mem.eql`/`mem.eqlBytes` for 0.14.1–0.17.0 (0.17.0 by its logical bit order), per-version retained translations, proofs on the generated casts, native probes of every version equal to the model, negative tests (non-byte source items, unequal bit sizes, non-LLVM non-byte lanes) and two killed mutants (`tests/roadmap/lang-long-tail`). [PR172](https://github.com/riventic/air2lean/pull/172): `f80` lanes: a lane pointer into `@Vector(n, f80)` is a bit-pointer on the lane's 80 bits (`Zig.Packed (Float fmt)`, `laneBits?` for floats), translated for 0.14.1–0.16.0 (`float_lanes.zig`, native probes equal to the model; 0.17.0 has no lane-pointer evidence and is rejected); Zig 0.14.1/0.15.2 runtime-index lane stores: the exporter writes `vector_store_elem`'s operands, `Canon.dropDeadRuntimeLanePtrs` drops the unread runtime lane pointer before it, and the store is the store through the lane pointer of lane `i` (`Zig.storeLaneAt`; `storeLaneAt_lt`/`storeLaneAt_ge` in `ZigLean/VecMem.lean`; `runtime_lanes.zig` with `u9`, `u24`, `bool` and `f80` vectors and a local filled at runtime indices, native probes of both versions equal to the model, `ProofsRuntimeLanes.lean`: in-bounds stores are lane stores, out-of-bounds is the `outOfBounds` panic); negative tests (another backend, a read runtime lane pointer) and two killed mutants (`tests/roadmap/lang-long-tail`). Remaining: other LLVM targets (s390x, wasm32 and others reject non-byte lanes in memory), the self-hosted and C backends (their element-stride vector layout is rejected), 0.17.0 lane pointers and legacy schema-11 files stay rejected.
