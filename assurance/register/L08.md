id: L08
title: Packed representations and bit pointers
status: partial
row: [PR103](https://github.com/riventic/air2lean/pull/103) merged with bounded byte permutation controls. [PR125](https://github.com/riventic/air2lean/pull/125): bit-pointer loads and stores touch only the field's bits through defined-bit masks (`Byte.mask`, `writeField`), a store of `undefined` makes only the field's bits undefined, and `ZigLean.PackedLemmas` proves the frame; the checker compares every exported packed field pointer with the model's layout (`PACKED_LAYOUT`) and rejects bit-pointers without a packed bit size. Soundness fix: a byte-aligned field reached through a nested bit-pointer (`&reg.inner.c`) was addressed without the base's bit offset (wrong host byte); the emitter now adds it. [PR135](https://github.com/riventic/air2lean/pull/135): compiler export `packed_fields.zig` (`air-fresh/0.16.0/llvm` from a patched 0.16.0 compiler and `x86_64` from the self-hosted backend, `compiler-provenance.json`), translated to `PackedFieldsFresh`/`PackedFieldsX86` with kernel-checked proofs for every function, and native tests of the defined-behaviour functions on aarch64-macos (ReleaseSafe and Debug). The real compiler differs from the hand-written AIR: field pointers of a global fold to constant pointers, `&reg.inner.c` is a bit pointer (`*align(4:8:3) u8`), `reg.inner = .Ellipsis` is two stores; the model handles both forms. Batch D (PR "Roadmap batch D: L08 L07 T03 L04"): `packed_fields.zig` passes natively on x86_64-linux (Docker) for 0.14.1-0.17.0, LLVM ReleaseSafe/Debug and the self-hosted backend, with the values the hand-written AIR's proofs give (including the byte-pointer `innerC`); packed unions, floats and (0.14.1/0.15.2) vectors as packed-struct fields, through bit-pointers and whole-value casts, with determined-bit masks (a NaN or an undefined union bit is undefined in memory, never the model's choice); packed-union constants made from bits; `tests/roadmap/packed-casts` with kernel-checked results for every version equal to native x86_64 outputs; lane pointers into a vector field, which 0.14.1/0.15.2 miscompile, are rejected (`docs/upstream/packed-vector-lane-ptr.md`). Remaining: pointer fields (0.14.1/0.15.2 only; the model's pointers carry provenance, not bits, and making packed values memory-dependent would change the pure packed model of 0.16/0.17), partly undefined packed values (`.unspecified` on a whole-struct load), big-endian packed structs with float fields, a compiler export of a byte pointer through a nested bit-pointer (no version emits one).
