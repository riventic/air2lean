id: T02
title: Parameterized pointer and machine integer widths
status: partial
row: [PR126](https://github.com/riventic/air2lean/pull/126): the profile's pointer width (`Zig.PtrWidth`) parameterizes pointer and optional-pointer encoding, slices, lengths, `usize` arithmetic, addresses and allocation overflow (`ZigLean/Mem/Width.lean`; the `.w64` definitions are the 64-bit model); one source exported for wasm32-freestanding, wasm32-wasi and x86_64 uses each target's real layouts, and `PointerWidth/Proofs.lean` proves its boundary and overflow behavior under both profiles (`@mulWithOverflow`, increments, bounds checks, `alloc` overflow at 2^30 on wasm32 only, stored layouts); native layout and boundary tests run on the host and under Node's WASI, and a layout of the other width is rejected. `@tagName` (exhaustive and non-exhaustive enums) and `@errorName` return a slice of the profile's width (`Zig.Slice32` on wasm32): `names.zig`, exported by Zig 0.17.1 and 0.16.0 for the same three targets (`exports.json`), is proved for all six translations (`PointerWidth/Names/V0_17_1/Proofs.lean` and its 0.16.0 instance: length, bytes, sentinel, bounds, unnamed value) and passes natively and under Node's WASI with both versions. `pointer_width.zig` is also exported by Zig 0.17.1 for the three targets (`exports.json`) and proved by `PointerWidth/V0_17_1/Proofs.lean`, the 0.16.0 proofs instantiated one namespace deeper (`scripts/fixtures.py instance`); `reject.zig`'s wasm32 rejections are checked on both versions' exports. The C integer types and pointer-sized integers (`c_ints.zig`, exported by Zig 0.17.1 and 0.16.0 for the same three targets): `PointerWidth/CInts/V0_17_1/Proofs.lean` and its 0.16.0 instance prove, for all inputs and every translation, the checked increment of each of `c_char` … `c_ulonglong` and `isize` against one width-generic specification (`c_long`, `c_ulong`, `isize` 32 bits on wasm32, 64 on x86_64), `@mulWithOverflow` on `c_ulong`, `isize` negation, the `c_long` → `c_int` narrowing (total on wasm32, checked on x86_64), the sign-extending `c_int` → `c_long`, and three extern-struct layouts through stored values (`{ int, long, short }` 12/24 bytes, `long long` 8-aligned on wasm32 too, `{ isize, usize }`), the width-generic closed forms stated once in `ZigLean/Mem/WidthLemmas.lean`; `long double` translates as `f128` (wasm32) / `f80` (x86_64), at offset 16 in `{ char, long double }` (`test_cli.py`), with no theorem (no wasm32 float-semantics target); native tests pass on aarch64-macos, x86_64-linux and under Node's WASI, and a `long long` exported with 4-byte alignment is rejected. Remaining: atomics, threads, futexes, Io, futures, vectors in memory, inline asm and C/allowzero pointers stay 64-bit only (rejected on wasm32); C integer types on profiles whose C ABI differs further (LLP64 Windows, unsigned `c_char` on aarch64-linux; not exported targets).
