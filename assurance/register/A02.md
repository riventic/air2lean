id: A02
title: Instruction semantics and target expansion
status: research
row: Design and recommendation in [docs/research/A02.md](docs/research/A02.md): an instruction-semantics library (`ZigLean/Isa`) keyed by the decoded instruction, replacing the opaque `airAsm_<hash>` for covered blocks, with the template decoded and its register footprint checked in the translator, each instruction anchored to a formal ISA specification (Sail Arm/ASL extraction where it extracts, cross-model vectors for x86) and to native execution on real CPUs, the assembler checked by an assemble-and-disassemble row (proposed ASM-07/ASM-08) and the CPU requirement derived from `profile.features` (admission ASM-09); x86_64 migrates the 19 allowlist entries first, aarch64 follows. `tests/roadmap/asm-semantics/check.sh` records native observations of 0.17.0 (x86_64 under Rosetta, aarch64 on the host): `lzcnt`'s encoding runs as `bsr` without LZCNT (`bsr(1)=0` against `lzcnt(1)=63`), aarch64 `udiv` by zero is `0` where x86 `divl` traps, `cntvct_el0` is an EL0 environment read, and at the baseline CPU the self-hosted x86_64 backend rejects `lzcnt`/`popcnt`/`rdrand` that LLVM assembles (upstream row 05). Finding: the baseline `asm_env` profile has no `rdrnd`/`popcnt`/`lzcnt` feature although the allowlist accepts them (ASM-04's CPU half is not derived from the profile). Remaining: all phases (decoder, x86_64 and aarch64 semantics, anchors, std crypto client).
