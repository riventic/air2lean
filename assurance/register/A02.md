id: A02
title: Instruction semantics and target expansion
status: partial
row: Design and recommendation in [docs/research/A02.md](docs/research/A02.md): an instruction-semantics library (`ZigLean/Isa`) keyed by the decoded instruction, replacing the opaque `airAsm_<hash>` for covered blocks, with the template decoded and its register footprint checked in the translator, each instruction anchored to a formal ISA specification (Sail Arm/ASL extraction where it extracts, cross-model vectors for x86) and to native execution on real CPUs, the assembler checked by an assemble-and-disassemble row (proposed ASM-07/ASM-08) and the CPU requirement derived from `profile.features` (admission ASM-09); x86_64 migrates the 19 allowlist entries first, aarch64 follows. `tests/roadmap/asm-semantics/check.sh` records native observations of 0.17.1 (x86_64 under Rosetta, aarch64 on the host): `bsr(1)=0` against `lzcnt(1)=63` (`lzcnt`'s encoding runs as `bsr` without LZCNT, by the Intel and AMD manuals), aarch64 `udiv` by zero is `0` where x86 `divl` traps, `cntvct_el0` is an EL0 environment read, and at the baseline CPU the self-hosted x86_64 backend rejects `lzcnt`/`popcnt`/`rdrand` that LLVM assembles (upstream row 05). Done (maintainer decision 2026-11-24, D1; phase 3 of the plan, by mnemonic): the CPU features of every inline-asm instruction come from one table (`Air2Lean/AsmFeatures.lean`: x86_64 and aarch64, Zig/LLVM feature names, compared with the Zig compiler's encoding tables by `tests/roadmap/asm-semantics/check-feature-table.sh`); `checkAsmCpuFeatures` rejects an asm block, allowlisted or declared by a device contract, with an instruction whose feature `profile.features` lacks or that is not in the table, and `--assume-asm-cpu-features <f,...>` admits named features only (premise ASM-09, recorded in the header with the features). This closes the finding that the baseline profile has no `rdrnd`/`popcnt`/`lzcnt` although the allowlist accepted them, and a second one: a device contract that declared `rdrand` skipped the check. Done (maintainer decision 2026-11-24, decision 1; phases 1 and 2 for x86_64): an x86_64 instruction model (`ZigLean/Isa/X86.lean`: `mov add sub and or xor inc dec neg not bswap lzcnt tzcnt popcnt bsr bsf xchg div` at 8 to 64 bits, faults `#DE` as `trap` and architecturally open results as `unspecified`, premise ASM-07); the translator decodes each block of a `semantics := .isa` allowlist entry (12 of the 19 x86_64 entries) from the one template scanner (`Air2Lean/AsmIsa.lean`) and emits it as `def airIsa_<hash>` over the model with a kernel-checked footprint check (`airIsa_<hash>_wf`) and, for a faulting block, its own fault guard (`Zig.Asm.isaFault`); a template outside the model or a block whose operands do not match the instructions is rejected, never approximated, and an entry whose fault condition disagrees with the model is rejected. `Proofs/Asm/Proofs.lean` and `tests/roadmap/asm-effects` prove the wrappers from the definitions with no instruction hypothesis; the differential test runs the generated wrappers against the native instructions (the `@[csimp]`/`sorry` archive is gone); `tests/roadmap/asm-wrappers` cross-checks each definition against an independent interpretation of its template; `ZigLean/Isa/X86Vectors.lean` checks the recorded native vectors; `scripts/claims.py` lists ASM-07 for every claim whose closure reaches the model. Remaining: placement independence of a checked block as a Lean theorem (ASM-07 item 4), the assemble-and-disassemble row (ASM-08), `rep` string semantics (phase 5), aarch64 (phase 4), anchors to a formal ISA specification, vector and crypto instructions (phase 6).
