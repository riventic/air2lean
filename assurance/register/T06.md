row: [PR120](https://github.com/riventic/air2lean/pull/120): assurance/build-modes.json + scripts/build-modes.py check: a qualification record per optimize mode x backend pair; ReleaseSafe/llvm is qualified (probe profile and command evidence, analyzed-AIR claim with stated premises); ReleaseFast/llvm is unqualified pending native observations; fast-math and shipping-binary semantics are excluded with guard text checked in the sources. [PR129](https://github.com/riventic/air2lean/pull/129): native differential run records (`assurance/build-mode-runs/`, `build-modes.py record`/`check`) for 0.16.0 aarch64-macos and x86_64-linux in Debug, ReleaseSafe, ReleaseFast and ReleaseSmall on LLVM: ReleaseSafe/Debug 0 mismatches; ReleaseFast/ReleaseSmall exclude the 4975 model-throwing inputs (`ub_excluded`) and are qualified for no-illegal-behaviour transfer with one stated exception, float `@divExact` with an inexact quotient (85 cases; ReleaseSafe does not detect it; reproducer committed); CI re-runs the x86_64-linux LLVM modes against the records. stage2_x86_64 stays unqualified with triaged divergences on legal inputs (float `@mod`, narrow packed-union sign extension, f80 signed-zero min/max; examples/asm does not compile). [PR135](https://github.com/riventic/air2lean/pull/135): aarch64-linux run records for 0.16.0 in Debug, ReleaseSafe, ReleaseFast and ReleaseSmall on LLVM (`assurance/build-mode-runs/`, recorded from `scripts/diff.sh` in a native `linux/arm64` container, no instruction emulation); `floatops` and `floatconv` are left out (the translation has no aarch64-linux float model: 586 typed f80/fused-multiply mismatches, reproducer committed), so the runs have 0 mismatches and ReleaseFast/ReleaseSmall exclude 4591 model-throwing inputs; CI job `build-modes-aarch64-linux` (`ubuntu-24.04-arm`) re-runs all four modes against the records. The earlier hosted-runner loss on ReleaseFast/ReleaseSmall was a core-dump storm (the image pipes each of ~700 crashing children to apport/systemd-coredump); the diff harness now contains every child (not dumpable, no core file, 4 GiB address-space cap, parent-death signal) under a 20 s per-case deadline (`tests/diff/common.zig`, `compat.zig`), and the four modes plus `record --verify` pass on the hosted runner in about 16 minutes. (The aarch64-linux float model and the aarch64-macos re-recording were done in PR143.) [PR172](https://github.com/riventic/air2lean/pull/172): stage2_x86_64 is qualified for x86_64-linux in ReleaseSafe and Debug (tested-input agreement) and ReleaseFast (no-illegal-behaviour transfer): the translator rejects the two backend divergences on a `stage2_x86_64` profile (`CheckCtx.checkStage2Backend`: a float `@mod`, whose self-hosted lowering adds the divisor once; a signed `packed union` field narrower than a register, which the backend does not sign-extend, native probe of 0.16.0/0.17.0), with real self-hosted exports of both reproducers as negative tests (`stage2_rules.py`, rejected under stage2, accepted under stage2_llvm); f80 signed-zero `@min`/`@max` is unspecified since PR143; each stage2 run tests the backend's own translation (`scripts/stage2-translations.py` exports every example with `-fno-llvm`, translates it under that profile and requires it to equal the committed model; rejected examples `floatops`, `layout` and the uncompilable `asm` are `excluded_examples`); re-recorded runs: 34343 cases, 0 mismatches in all three modes. Correspondence beyond the committed inputs: `scripts/fresh-inputs.sh SEED` regenerates the inputs from another seed in a check tree and runs the differential test without the per-input pins on the examples that have none on the host (model exclusions stay exclusions, any disagreement fails; the summary records the seed; pinned examples such as x86_64-linux `floatops` are not re-tested); CI runs it on every commit with a seed from the commit hash; locally (aarch64-macos, seed 0x5eed0123) 85966 fresh cases, 0 mismatches ([docs/build-modes.md](docs/build-modes.md)). Remaining: ReleaseSmall/stage2_x86_64 (its harness binaries die with SIGBUS under the emulated container; needs a native x86_64-linux host); stage2_x86_64 AIR is still translated only with `--allow-unqualified-build-mode`; float `@mod` is rejected rather than modelled for stage2; 0.17.0 build-mode records; correspondence is still bounded to the inputs run.
