row: Typed diagnostics and bounded Outcome witness/replay candidate. [PR120](https://github.com/riventic/air2lean/pull/120): scripts/counterexample.py writes replayable counterexample bundles (input, full schedule prefix, violated contract, AIR candidate sites); only replayed failures are counterexamples, while timeouts, caps and fuel limits are unsolved and unreplayed failures stay candidates; a real-atomics relaxed message-passing race is localized end to end. [PR129](https://github.com/riventic/air2lean/pull/129): counterexample bundles carry I05 source spans (`source_span`, `statement`/`declaration`/`unavailable_in_AIR`); `goal-search` evaluates the generated Lean (`lake env lean --run`, no Zig) on boundary/seeded inputs against a stated postcondition and replays the first violation in a fresh Lean process (only then a counterexample; a bounded miss, timeout or fuel limit is unsolved, an exhausted finite domain is no_failure); sequential from-case bundles replay without Zig (`lean_sequential`) and schedule bundles through the Lean interpreter (`--interpret`); a seeded off-by-one loop yields its counterexample input, the correct loop none. [PR135](https://github.com/riventic/air2lean/pull/135): spans from a real patched export (`tests/roadmap/counterexamples/native`): the off-by-one `sumUpTo` counterexample carries its declaration span and the overflowing `scale` counterexample the `mul_safe` statement span at the line and column of `*`; `--zig-source` adds a Zig-side replay (`replay.zig_native`: stock Zig builds the function with the shared harness, runs the violating input in a child process and compares with the Lean outcome by the differential rule), and a violation that is itself an illegal or model-panic outcome lists the sites of that failure; a `lean-eval` timeout kills the whole process group. [PR154](https://github.com/riventic/air2lean/pull/154): a sequential `from-case` bundle of any shape the production differential covers (structs, slices and memory buffers, optionals, error unions, floats, allocators) replays through `replay.kind = diff_row`: the example's own harness and the built Lean runner (`difftest`) rerun on exactly the recorded input row, verified only when both fresh lines equal the recorded ones, `not_reproduced` (unsolved) when a host or model difference changes either; spans inside inlined calls are exact when the callee exports `src` (the callee's statement and file) and every inlined site lists its `inline_chain` of call sites, so a site whose own span is `unavailable_in_AIR` is still placed at where it is reached from. [PR907](https://github.com/riventic/air2lean/pull/907): goal search covers every value kind the translator emits, by one type model (`scripts/lean-eval.py`: one class per kind, resolved by walking the generated Lean type and the AIR type table together): integers, `bool`, `void`, enums, structs, tagged unions, optionals, error unions and read-only slices, nested in any way, in `Zig.Result` functions and in `Zig.MemM` functions with value-only signatures (run from `mem0 .fresh`); anything else is `unsolved: unsupported` with the reason; a violation of a sampled domain is shrunk to a locally minimal input; the replay runs the native program on the same values and decides the stated postcondition on the native outcome itself (`replay.zig_native.postcondition`), and `from-case --spec` states a postcondition for a sequential differential row; `native/shapes.zig` has per kind a seeded bug (a minimal counterexample, reproduced natively) and a correct twin (none reported). Remaining: a stated postcondition for functions over places in memory (pointers, slices the function writes: the goal search and `from-case --spec` reject them, and their row replay confirms the differential outcomes only), floats and vectors; an export without `src` has no spans.
