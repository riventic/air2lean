row: [PR100](https://github.com/riventic/air2lean/pull/100) merged with bounded alignment and three-version controls. [PR126](https://github.com/riventic/air2lean/pull/126): aarch64-linux-gnu and aarch64-macos-none are qualified separately: native probes run only on their own host (`scripts/aarch64-abi.py`: unusual integer widths, f16 to f128 and `c_longdouble` layouts and results, f80 invalid encodings, atomic cells including u24/u40 with padding, the widest atomic, the cache line, L09 vector images), Zig 0.16.0 expected results are versioned per profile, and Lean checks with kernel-checked layout tables are tied to each file; host exclusions never count as matches. [PR135](https://github.com/riventic/air2lean/pull/135): expected results for Zig 0.15.2 and 0.14.1 beside 0.16.0 on each aarch64 profile (aarch64-linux-gnu measured in a native `linux/arm64` container, aarch64-macos-none on Apple silicon), synchronization-boundary probes (every `@atomicRmw` operation on u8/i8, u24/i24, u40/i40, u64/i64 and u128/i128 cells, every ordering the compiler accepts for load, store, RMW and `cmpxchg`, bool, enum, pointer, f32 and f64 cells, three threaded litmus tests with deterministic outcomes) and twelve compile-reject limit programs; `Model.lean` checks each file and lists the declared divergences on both profiles (a signed `@atomicRmw` `Max` on a negative padded `i24`/`i40` cell keeps the negative cell; 0.14.1 and 0.15.2 soft-float `f80`/`f128` `@sqrt` is `f64`-precise only); CI runs the aarch64-linux job (`ubuntu-24.04-arm`) for the three versions and the macOS job for each. Remaining: aarch64 AIR stays outside the translator's accepted profiles (no native differential test or proof build on those hosts); the padded signed `Max` divergence is declared, not fixed (the translator's atomic checker does not reject padded widths); weak-ordering outcomes, instruction-level ordering strength, futex/mutex behaviour, atomic `f80` and non-baseline CPU features are unprobed; Zig 0.17.0 has no expected files.
