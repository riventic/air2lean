title: Architecture-specific ABI qualification
status: partial
row: [PR100](https://github.com/riventic/air2lean/pull/100) merged with bounded alignment and three-version controls. [PR126](https://github.com/riventic/air2lean/pull/126): aarch64-linux-gnu and aarch64-macos-none are qualified separately: native probes run only on their own host (`scripts/aarch64-abi.py`: unusual integer widths, f16 to f128 and `c_longdouble` layouts and results, f80 invalid encodings, atomic cells including u24/u40 with padding, the widest atomic, the cache line, L09 vector images), Zig 0.16.0 expected results are versioned per profile, and Lean checks with kernel-checked layout tables are tied to each file; host exclusions never count as matches. [PR135](https://github.com/riventic/air2lean/pull/135): expected results for Zig 0.15.2 and 0.14.1 beside 0.16.0 on each aarch64 profile (aarch64-linux-gnu measured in a native `linux/arm64` container, aarch64-macos-none on Apple silicon), synchronization-boundary probes (every `@atomicRmw` operation on u8/i8, u24/i24, u40/i40, u64/i64 and u128/i128 cells, every ordering the compiler accepts for load, store, RMW and `cmpxchg`, bool, enum, pointer, f32 and f64 cells, three threaded litmus tests with deterministic outcomes) and twelve compile-reject limit programs; `Model.lean` checks each file and lists the declared divergences on both profiles (a signed `@atomicRmw` `Max` on a negative padded `i24`/`i40` cell keeps the negative cell; 0.14.1 and 0.15.2 soft-float `f80`/`f128` `@sqrt` is `f64`-precise only); CI runs the aarch64-linux job (`ubuntu-24.04-arm`) for the three versions and the macOS job for each. [PR143](https://github.com/riventic/air2lean/pull/143): aarch64-linux (gnu) AIR is translated, differentially tested and proof-built natively for 0.14.1–0.16.0 (the `aarch64-linux` job). [PR172](https://github.com/riventic/air2lean/pull/172): Zig 0.17.0 aarch64-linux is a declared translation path (`compatibility.json`, `assurance/target-matrix.json`): the `aarch64-linux` job builds the patched 0.17.0 natively, exports the examples' AIR on the host, compares it with the goldens (new `air-linux-aarch64/` overlays for `floatops` and `floatconv`), translates (`Gen-linux-aarch64.lean`), runs the differential test (0 mismatches, 86209 cases, recorded in a native `linux/arm64` container) and builds the proofs, as for 0.16.0/0.15.2/0.14.1; the padded-width `cmpxchg` and `.Max`/`.Min` rows are no longer declared divergences: `Model.lean` accepts a divergent row only when it is an operation the translator rejects (`PADDED_ATOMIC`, `rejectedByTranslator`; for an `atomic` row only its `cmpxchg` may differ), and a wider native probe (`u7`/`i7` to `u56`/`i56`, 0.14.1–0.17.0) shows every divergence is such an operation ([docs/aarch64-abi.md](docs/aarch64-abi.md)); weak ordering: nine litmus tests (MP, SB, LB, CoRR, WRC, IRIW with relaxed, release/acquire, acquire and `seq_cst` variants, 100 000 rounds each) observed natively on both profiles for 0.14.1–0.17.0 (`tests/roadmap/weak-ordering/observed/`, re-observed by the `aarch64-linux` and `macos` jobs), every observed outcome checked to be an outcome of the model's atomics by exhaustive exploration of `atomicLoadAt`/`atomicStoreAt` (`Litmus.lean`, forbidden outcomes checked at elaboration; observed: weak MP and IRIW on Apple silicon, SB on both; [docs/weak-ordering.md](docs/weak-ordering.md)). Remaining: instruction-level ordering strength, futex/mutex behaviour, atomic `f80` and non-baseline CPU features are unprobed; build-mode records for 0.17.0 aarch64.
