id: P07
title: Proof-friendly and stable generation
status: complete
row: Completed (close-out review 2026-11-26; evidence at the end). PR93 deterministic names and PR94 scalar stable proof API merged. [PR120](https://github.com/riventic/air2lean/pull/120): air2lean --source-map-json writes a per-function source-map sidecar bound to its Lean output; scripts/semantic-fingerprints.py computes renumbering-invariant fingerprints folded over call-graph SCCs and an invalidation checker reports exactly the changed functions, their cycles and callers. [PR126](https://github.com/riventic/air2lean/pull/126): `--proof-api` emits source-named unfolding lemmas for every function (pure, memory, concurrent, error-returning, recursive) and per-loop body/again/body-unfold/step lemmas, proved by `rfl`, `eq_def` or `Zig.loop.eq_1` and indexed by an `air2lean-proof-lemmas-v1` record; renumbering and an unrelated generic instance keep lemma names and statements while a semantic change alters only that function's; sidecar v2 carries a build-time translator revision (digests of the CLI and every imported `Air2Lean` module) that is part of every fingerprint, and I04's module keys are bound to it. [PR154](https://github.com/riventic/air2lean/pull/154): every loop also gets a `B_loop<k>_spec` lemma, the loop specification rule of the function's monad (`Zig.loop_spec`, `Zig.loop_spec_mm`, `Zig.Conc.Proto.WP.loop`) instantiated at the loop's stable body and repeat test, so a client states an invariant, a measure and a post-condition and proves one iteration, with no reference to `<fn>.loop<id>`; kernel checked on the committed golden examples (pure, memory, concurrent, recursive loops) and renamed with the other loop names (`air2lean-proof-lemmas-v1` gains `spec`); sidecar v3 and the I04 manifest v3 carry a build-time runtime revision (digests of every `ZigLean` module in the import closure of `import ZigLean`, which each generated module imports) that is part of every fingerprint and module key, so a runtime change invalidates every proof interface (`runtime_changed`). Completed (close-out review 2026-11-26): `tests/roadmap/stable-generation/test_cli.py` (CI) shows both clauses on the shared golden AIR (recursion, pointers, errors, basic, variants) and on Zig 0.17.1's golden set (`basic`: schema 12, profile `abi64-le-v1`, the compiler's `__func_<n>` instance names). (a) Renumbered IDs, shifted lines, hashed storage names and an unrelated generic instance keep every fingerprint and proof-interface name (`added` is only the new instance), and `check_generic_instance` shows the same for another instance of a reached generic. (b) A one-instruction semantic change invalidates exactly that function, its recursion group and its transitive callers. `test_fingerprints.py` covers callers, cycles and malformed sidecars, and `test_cli.py` a sidecar bound to another module's output. The designated mutants `fingerprint-callers-not-invalidated`, `fingerprint-body-ignored`, `fingerprint-translator-revision-ignored` and `sidecar-runtime-revision-unchecked` (`tests/roadmap/mutation-map/mutants.py`) are each killed by `FingerprintTests`. Scope: `B_loop<k>_spec` instantiates the library loop rule, and the invariant and measure stay the client's. The runtime revision digests the closure of `import ZigLean`; proof libraries beyond it (`ZigLean.Sep`, …) do not change generated code and are bound by the I07 manifest's `runtime` link and by proof rebuilds. The other 0.17.1 goldens (pointers, errors, variants) still mix 0.15.2 files, and recursion has no 0.17.1 set, so the 0.17.1 run covers the examples whose golden set is entirely 0.17.1.
