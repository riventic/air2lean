row: [Storage PR105](https://github.com/riventic/air2lean/pull/105) merged with bounded error-storage and declared version generation/proof/runtime controls. [PR125](https://github.com/riventic/air2lean/pull/125): the error model is parameterized by the profile's `error_set_bits` (1–32, from `--error-limit`): width-parameterized storage operations (`ZigLean/Mem/ErrWidth.lean`; the default 16 bits keeps byte-identical output), layout and capacity checks, and proof-only `ZigLean.Mem.ErrWidthLemmas` (store/load round trips, error-union laws, `@errorFromInt`/`@intFromError` over an explicit `ErrorTable`, out-of-range codes); hand-written fixtures at 8, 10, 16 and 17 bits are translated, elaborated and executed. [codex/lang-long-tail](https://github.com/riventic/air2lean/tree/codex/lang-long-tail): error values as runtime parameters: Zig 0.14.1–0.17.0 never treat an error set or error union as one-possible-value, so a one-name `error{A}` parameter keeps its AIR `arg` (`Canon.onePossibleValue`, which also gives an enum one value only with a `u0` tag); this unblocks the 47 `std.Io.Threaded` `Syscall.fail(s, err: anytype)` instances; compiler exports of `error_params.zig` for all four versions translate to one text, with proofs (`orBoom_spec`, `forward_spec`, `viaFail_values`), native probes of every version equal to the model, negative tests and a forwarding mutant (`tests/roadmap/lang-long-tail`). [PR172](https://github.com/riventic/air2lean/pull/172): integer/error casts translate: the patched compiler writes the compilation's error numbering after analysis (`error-table.air2lean`, [air-json.md §Error table](docs/air-json.md#error-table)), the translator reads it (version and width must match), emits `errorTable` and translates `@intFromError`, `@errorFromInt` and its `cmp_lt(e)_errors_len` check (`Zig.intFromErrorIn`, `Zig.errorFromIntIn`; `intFromErrorIn_spec`, `errorFromIntIn_valid`); `@errorName` finds a name by code, and 0.14.1's `@errorName` is admitted when every code is below the sign bit; without the numbering the casts are rejected. `error_ints.zig` exports its native probe's own compilation at 16 bits (0.14.1–0.17.0) and 8 bits (`error_ints_w8`, 0.15.2–0.17.0; 0.14.1 rejected): codes, names, round trips and memory round trips equal the native program; `ProofsErrorInts.lean` proves the casts for every code and every numbered error; negative tests (no numbering, another version or width, a duplicate name, too many errors) and a killed mutant (the numbering guessed from the program's error set). Non-default widths: `error_width.zig` compiler exports and native observations for 0.17.0 (0.17.0 writes a `?E` code sign-extended into its padding bits at non-byte widths; the model leaves padding undefined, documented), the project workflow (`scripts/project.py`) accepts 1–32 bits, and the ABI probe checks the `anyerror` and `anyerror!u8` layouts at 8, 16 and 32 bits natively (x86_64-linux-gnu, aarch64-macos-none, 0.16.0 and 0.17.0; CI rows). Scope: x86_64-linux and aarch64-macos with LLVM; the numbering is per compilation, so a proof about codes is about the exported compilation.
